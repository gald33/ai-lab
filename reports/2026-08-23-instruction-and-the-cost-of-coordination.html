Four treatments, no effect

We set out to show that telling agents useful things improves how they coordinate. It didn't. What we found instead is where the loss actually sits — and that our instrument was too blunt to have answered the original question either way.

Experiments 005 (runs 005–007) and 006 (runs 001, 002a, 002)
claude-haiku-4-5 · 4 traders · 180-second episodes · Cobb-Douglas island

Four contents, from a 426-word protocol to a single paragraph. The obvious reading is the cost is in the adding. This report declines to draw it.

Why not

The run is a bigger effect than any treatment

One frozen block — r-ratios, hash 36cd95dc… — run twice on the same five islands. Against its control it came in at −0.242 (0 of 5) the first time and +0.271 (5 of 5) the second. Every seed flipped sign. Pooled over ten paired rounds: +0.015, 5 of 10.

What this costs us

It is not a labelling error — workspaces match arms in both result files, and only r-ratios boards carry the block's vocabulary. Both checked. So the four negatives above are not evidence that instruction hurts; they are evidence that this instrument cannot tell these treatments apart from doing nothing. Two stopping rules fired on differences of this size and should be read as not yet tested.

The claims that survive are absolute measurements — a level against a closed form, or a count. The ones that don't are between-cell differences. That line is worth carrying forward as a design rule, not treating as a coincidence.

A correction we made to ourselves

The floor answers one question, not two

After the solo run, this report's author wrote that the deficit in earlier runs was a trading failure. Too strong, and the owner caught it.

The solo run measures solution quality on a strictly easier problem — a lone agent has no access to half the joint one: who to trade with, at what rate, in what order. A harder problem being harder is not a failure at it.

  • Kept: autarky utility as a participation constraint. An agent below it would rather not have traded. No assumption about difficulty required.
  • Withdrawn: treating the solo score as the expectation for the joint score.

The correction is appended, dated, below the run's outcome — not edited into it.

The mechanism

Production is a bet placed before the outcome is known

Labour commits inside the same episode as the negotiating, so specialising is a wager on counterparties who may never answer. Cobb-Douglas makes a lost wager total: one good at zero is utility zero.

No disclosure hint can fix that, which is consistent with four of them not fixing it. What would address it is a change to the mechanism — letting an exchange be agreed before production settles, or letting proposals survive the bell — rather than a change to what agents are told.

Review targets

Where to attack this, in order

  1. Is the run effect the tool grant, or noise?

    Run 002 granted the keyed store to all cells, the only known instrument difference between the two runs whose signs disagree. Settled by re-running run 001's three cells under the current grant, same seeds — 15 rounds, 60 sessions. If the reversal follows the grant, a capability grant changed untreated behaviour invisibly, which is a finding in itself.

  2. The between-cell ordering of production quality

    The 0.97-alone versus 0.49–0.78-in-company gap is robust. The ordering among the three cells is exactly the difference five seeds cannot resolve. Don't build on it.

  3. The size of the trade gain

    1.04–1.07 is small, and excluding corner bundles biases it downward by an unknown amount. The direction is safe; the magnitude is not.

  4. Whether any of this generalises past one model

    Every number here is one model at 180-second episodes. The standing hypothesis — that a more capable agent has attention to spare for instruction, making the treatment effect a function of capability — is untested, and would need a 2×2 sized against a 0.25 effect, not 0.10.

Harness

Three runs died to infrastructure, not to agents

  • A gateway 502 on a manager read killed six rounds mid-run. Fixed with a bounded retry on transient reads.
  • A dropped connection — a transport error rather than a bad answer — went straight past that retry and killed nine rounds that had already played all ten episodes. Fixed by catching transport faults, and more importantly by isolating round failures so one round's death no longer destroys every other round's record.
  • One run's result file was never written, so its alive fraction and rescue count are not reported. Reconstructing them from message counts would be a self-report by another name.

Separately: the hosted board viewer reads the first fifty messages of a room and never advances, which reads exactly like a stalled run. Reported upstream.
